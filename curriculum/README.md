# All lessons 📚

22 short lessons. Do them **in order** — each one builds on the last.

## How each lesson folder works

```text
05-links-urls-and-paths/
├── README.md      📗 the easy lesson — start here
├── deep-dive.md   📘 the detailed version — every rule and exception
└── examples/      💻 real pages to open and play with
```

Read the easy lesson first. It takes 10–40 minutes. Come back to the full version later, when you want to go further.

Every easy lesson looks the same, so you always know where you are:

1. **In one sentence** — the whole idea, short.
2. **Examples** — small code, with ✅ right and ❌ wrong.
3. **⚠️ Careful** — the traps.
4. **✅ Remember** — the key points.
5. **🎯 Try it** — a small task (answers are hidden until you click).

## What this course adds to a typical HTML course

Compared with the original four-day outline it grew from, these topics were **added** or **corrected**:

- **Added:** how the web works (HTTP, DNS, hosting); standards vs quirks mode; tags you can leave out; what can go inside what; `dfn`, `data`, `menu`, `search`, `hgroup`; image maps; SVG, canvas and MathML; picture formats; `fetchpriority`; captions vs subtitles vs descriptions; why some sites refuse framing; `datalist`; all 22 input types and their traps; `inputmode`/`enterkeyhint`; checking forms from JavaScript; WCAG 2.2; the five rules of ARIA; six ways to hide things; structured data; `hreflang`; robots.txt vs `noindex`; popovers; `command`/`commandfor`; one-at-a-time accordions; Web Components and declarative shadow DOM; HTML5 APIs; CSP and SRI; Core Web Vitals; Baseline; the list of obsolete tags; HTML vs XHTML; Git and going online.
- **Corrected or tightened:**
  - The "document outline": the outline idea was removed from the rules — only heading levels matter.
  - `<button>`'s default type: it's `submit` inside every form, not just "usually".
  - `target="_blank"`: modern browsers already add `noopener`.
  - Paths starting with `/`: they break on `file://` and on GitHub Pages project sites.
  - `<cite>`: it's for the titles of works, not people's names.
  - `type="email"`: it accepts addresses with no dot after the `@` part.
  - `pattern`: it uses the `v` flag, which changes which characters need a backslash.
